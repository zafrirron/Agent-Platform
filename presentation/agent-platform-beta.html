The Problem

AI agents are powerful — but undisciplined

🎲

Inconsistent quality

Same task, different session — completely different results. No standards. No gates.

🔀

Multi-IDE chaos

Claude, Cursor, Codex — each in isolation. File conflicts. Lost context between switches.

🔁

Context re-explaining

Every session: re-explain the stack, rules, patterns. Hours of setup for minutes of work.

🔓

No enforcement

Agents skip tests. Ignore security. No playbook. No critic. No proof of correctness.

The Solution

A coordination layer that makes AI agents disciplined

Installs a complete agentic development environment into any repo. One command.

🔗

Quality Gates

Design before code. Standards enforced. Every time.

The platform gates quality at every stage — not as suggestions, but as hard stops.

🛑 Design Gate — no code without approval
Trivial fix: one sentence + "ok"
Small feature: 2–3 sentence design + confirmation
New module / endpoint: written design + explicit approval
Cross-cutting: Architect review + ADR + alternatives
Silence ≠ approval  ·  No code without explicit confirmation
⚙️ Code Standards — always enforced
SOLID principles SRP · OCP · LSP · ISP · DIP — enforced at design review
DRY 3+ duplicate blocks → Critic flags, abstraction required
Lint gate Blocks CI same as a failing test — not optional

Dual Rules Model

Platform rules upgraded. Your rules untouched.

Every expert file has two independent sections. Upgrade only touches the top one.

PLATFORM SECTION — updated on --mode=upgrade

OWASP rules · quality gates · done-when checklists · security rules from web audit. Maintained by the platform. Every upgrade makes your agents smarter.

PROJECT SECTION — NEVER overwritten

Your team's specific rules · stack conventions · naming standards · your domain-specific gates. Added by your agents. Survives every upgrade forever.

Verified in E2E test — PROJECT rule survived a full upgrade

### Auth and secrets
- JWT: verify algorithm ≠ "none"
- No tokens in localStorage (F001)
- SSRF: block 169.254.x.x ranges (F007)
<!-- PLATFORM:END -->

<!-- PROJECT:START -->
### Team rules — Acme Corp
- All endpoints must respond in <200ms
- Use our internal auth SDK v3

CWE Top 25

Common Weakness Enumeration — catalog of most dangerous software security weaknesses.

SOLID principles

5 object-oriented design principles: Single responsibility · Open/closed · Liskov · Interface segregation · Dependency inversion

Wikipedia →

ADR — Architecture Decision Record

Short document capturing a hard-to-reverse architectural decision and why it was made.

adr.github.io →

OpenAPI / Swagger

Industry standard for describing REST APIs. Docs expert generates publish-ready OpenAPI specs automatically.

swagger.io →

OIDC — OpenID Connect

Short-lived token auth for CI runners — more secure than long-lived static secrets.

openid.net →

SBOM — Software Bill of Materials

Complete list of all software components in a build. Required for supply chain security compliance.

cisa.gov →

CVE / CSRF / SSRF

CVE = known vulnerability in a specific library · CSRF = cross-site request forgery attack · SSRF = server fetches attacker URLs

cve.mitre.org →

DRY · N+1 · CQRS

DRY = Don't Repeat Yourself · N+1 = database query anti-pattern · CQRS = separate read/write controllers
