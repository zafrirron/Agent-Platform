Quality Gates

Not suggestions. Hard blocks until resolved.

🛑 Design Gate — no code without design confirmation
Trivial fix → one sentence + "ok"  ·  Small feature → 2–3 sentence summary
New endpoint → written design + explicit approval  ·  Cross-cutting → Architect + ADR
Silence ≠ approval. Scales with task size. No friction for small changes.
🔒 Security Gate (Step 5a) — fires automatically
Any feature touching endpoints, auth, or data input → Security expert reviews before Critic.
No user action needed. OWASP Top 10, LLM injection, input validation, secrets check.
🔍 Critic Review — adversarial, 10 dimensions
[SECURITY] [CORRECTNESS] [TEST] [COMPLETENESS] [PERFORMANCE] [DESIGN] [DEPENDENCY] [ACCESSIBILITY] [OPERABILITY] [BC]
0 Critical, 0 High before anything is marked done. Findings include file:line + fix.
Cross-framework mode: different model reviews cold — different blind spots, genuine independence.
🏢 Enterprise readiness — NFR · PRR · compliance
Measurable targets in nfr-log.md · go-live gate via production-readiness
SOC 2 / ISO SDLC prep via compliance-review · WCAG 2.2 + UX rules in Frontend expert
⚠️ BC Check — backwards compatibility
Any change to an API, schema, config key, auth mechanism, or exported interface triggers:
⚠️ BC BREAK — [what] · Affected: [who] · Migration: [how] · Action required
All 9 experts + Critic [BC] dimension + 5 playbook gates. Blocks until explicit approval.
Example: "Add user authentication"
1 Design Gate → cross-cutting scope, ADR required
2 BC Check → auth header format is a new contract, documented
3 Backend implements JWT — sub claim, owner field, bcrypt
4 Step 5a: Security gate fires automatically
5 Test agent: 41 tests written, coverage gate checked
6 Critic: 10-dimension review — 0 Critical, 2 High resolved
✓ Done — nothing skipped, nothing assumed

This is the code review that happens before the PR —
from an adversary with no ego.

Cross-IDE Coordination

Your IDE choice. Our shared context.

📋 Shared registry — no conflicts

Before any agent touches a file, it checks registry.yaml. If another IDE is active on the same files, it offers coordination — not silent overwrite.

🔒 Handoff log — context preserved

Session end writes: goal, files changed, commit hash, Critic reviewed. Next session — any IDE, any model — reads this and picks up from there. No re-explaining.

🔍 Cross-framework Critic

When you switch tools, the new session offers a cold review of what the previous model built. A different model has different blind spots — that's the value, not a bug.

🖱 Cursor: multi-model + Plan mode

All Cursor models inherit .cursor/rules/ and .cursor/commands/ (/session-start, /implement, …). Model switch mid-task → session-end first.
Plan mode: after plan approval, /implement resumes add-feature Step 3 with full gates (5a Security, 5b Critic).

Dual Rules Model

Platform rules upgraded. Your rules untouched. Forever.

Every expert file has two independent sections. Upgrade only touches the top one.

PLATFORM SECTION — replaced on upgrade

OWASP rules · quality gates · done-when checklists · security rules · BC checks. Maintained by the platform. Every upgrade makes your agents smarter automatically.

PROJECT SECTION — NEVER overwritten

Your team's stack · naming conventions · domain-specific rules · performance requirements · internal SDK usage. Added by your agents. Survives every upgrade, permanently.

On upgrade

PLATFORM section: replaced with latest OWASP + BC rules

Always preserved

PROJECT section: your rules stay intact, forever

<!-- PLATFORM:START -->
### Backwards compatibility
- BC break → ⚠️ notice before any code
- Auth changes: token transition period required
- Schema drops: expand → migrate → contract
<!-- PLATFORM:END -->

<!-- PROJECT:START -->
### Team rules — [Your Team]
- All endpoints must respond in <200ms
- Use internal auth SDK v3, not raw JWT
- PostgreSQL only — no NoSQL allowed
- Feature flags via LaunchDarkly, never env vars
<!-- PROJECT:END -->

PROJECT section rules are discovered and filled in by the agents during your first sessions — you don't write them manually.
